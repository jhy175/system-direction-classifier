# 知识库数据库与导入

知识库和现有用户、权限、菜单、团队共用 MySQL 业务库 `direction_classifier`。`direction_classifier_test` 用于独立验收。应用以 `dev,mysql` 启动时，Liquibase 通过 `db.changelog-users.yaml` 加载知识库迁移。

## 表与版本

| 表 | 主要内容 |
| --- | --- |
| `demo_taxonomy`、`demo_discipline` | 体系和体系内唯一的字符串学科代码。教育部代码保留前导零 |
| `demo_knowledge_base`、`demo_knowledge_version` | 所有者及共享范围、草稿与版本、最新及默认指针、来源版本、清单和校验报告 |
| `demo_knowledge_discipline` | 版本内代码和名称快照、完整画像 JSON、原始定义、精判文本及来源文件 |
| `demo_knowledge_summary` | 版本内的学科召回摘要、关键词和生成依据 |
| `demo_knowledge_cluster`、`demo_knowledge_cluster_member` | 簇描述、关键词、顺序，以及同版本的学科成员关系 |
| `demo_knowledge_seed_paper`、`demo_seed_paper_discipline` | 种子论文快照、原始文献标识、来源、学科归属及参与生成标记 |
| `demo_knowledge_asset`、`demo_knowledge_index` | 版本的文件清单和可选向量索引记录 |
| `demo_knowledge_import`、`demo_knowledge_import_item` | 导入批次、解析规则、来源位置、校验及采用结果 |
| `demo_file_asset`、`demo_asset_reference`、`demo_resource_grant` | 通用文件、文件引用和对象授权 |

画像的核心任务、边缘任务、交叉任务、区分规则及来源特有字段保存在 `portrait_json` 中。导入时从同一对象提取定义及扩充文本。精判文本依据当前算法的拼接规则生成并单独计算哈希。后续编辑接口需在画像变化时检查文本投影、摘要和其他派生资源的更新状态。

每个知识库最多有一个草稿。资源行只能写入草稿，保存后的版本和资源行由数据库触发器保护。复合外键约束同一版本的学科、摘要、簇成员和论文归属。簇成员表允许一个学科关联多个簇，当前算法的导入预检要求其输入形成完整、无重复的归簇。

## 当前算法资源

导入器从算法项目的 `api_core.py` 读取 `SYSTEMS` 的资源路径。每个体系首次导入为一个内置知识库的第 1 版，并设为默认版本。

| 体系 | 画像目录 | 画像 | 召回摘要 | 学科簇 | 簇成员关系 | 原始文件 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `moe` | `outputs/LLM_portraits/` | 95 | 95 | 18 | 95 | 97 |
| `wos_ssci` | `outputs/LLM_portraits_wos_SSCI/` | 58 | 58 | 14 | 58 | 60 |
| `wos_scie` | `outputs/LLM_portraits_wos_SCIE/` | 178 | 178 | 31 | 178 | 180 |
| 合计 | | 331 | 331 | 63 | 331 | 337 |

摘要和簇文件来自 `SYSTEMS` 所指向的 `outputs/llm_hier_recall_cache/`。各体系通过学科代码关联。SSCI 缓存中旧的画像目录记入来源信息，资产关联以当前配置为准。缓存缺少历史生成输入的哈希时，来源标记为 `imported_unknown`，并保留缓存定义与导入画像的比对结果。

首批数据覆盖当前 API 使用的画像、摘要和簇。内置知识库的所有者是启用的 `admin` 管理员账号。种子论文和相似度附件可以从知识库草稿补充。

## 工作台使用方式

以 MySQL 配置启动并登录后，在工作台打开「学科知识库」。列表提供名称搜索、体系和范围筛选及分页。打开已保存版本可查看画像、摘要、簇、论文和附件，导出指定版本的资源 JSON。

所有者可从已保存版本创建草稿，编辑完整画像、摘要、簇成员、种子论文及相似度附件。每次资源保存写入数据库草稿并推进修订号。版本发布固定清单和校验报告，已有默认版本由所有者单独调整。可从已有版本创建个人副本，也可按团队共享自建知识库。

导入使用同一体系的知识库 JSON。页面先列出资源数量和重复或缺失关联，确认后原文件和导入明细一并保存。相似度资源接受 CSV、TSV 或 JSON 附件，可单独下载。摘要提取和关键词分组提供本地规则预览，确认后写入草稿。模型生成、正式方法版本的引用查询以及识别运行使用数据库版本，依赖相应模块的后续接入。

自动验收通过独立测试应用运行 `python scripts/test-knowledge.py`。测试报告保存在 `logs/knowledge-api-test.json`。

## 复现导入

使用项目的 MySQL 启动脚本和应用启动脚本完成 Liquibase 迁移。从本项目根目录执行以下命令，算法目录可以换成实际位置。启动命令见 [MySQL 启动说明](../zh-CN/user-module-completion.md#3-初始化与正常使用)。

```powershell
$algorithmDir = (Resolve-Path -LiteralPath '../../学科交叉算法接口/direction-classifier').Path
$algorithmPython = Join-Path $algorithmDir '.venv/Scripts/python.exe'

& $algorithmPython .\scripts\import-knowledge.py --algorithm-dir $algorithmDir
& $algorithmPython .\scripts\import-knowledge.py --algorithm-dir $algorithmDir --database direction_classifier --apply
& $algorithmPython .\scripts\import-knowledge.py --algorithm-dir $algorithmDir --database direction_classifier --verify
```

第一条命令预检资源并打印数量和清单哈希。应用模式使用已配置的本机应用账户，校验 MySQL 实例身份，并在同一个事务内写入三套资源。相同清单再次导入时复用已保存版本。清单变化时生成新版本并更新最新指针，原默认指针继续指向之前选定的版本。校验模式读取已保存版本，逐条核对完整画像、精判文本、摘要、关键词、簇成员及顺序和原文件内容。

原始文件按内容哈希归档到项目的 `.local/knowledge-assets/sha256/` 下。资源清单记录原始相对路径和 SHA-256，文件资产表记录存储键。备份和恢复时应配套保存 MySQL 数据与该目录。

## 查询已保存版本

```sql
SELECT t.code AS taxonomy_code, b.name, v.id AS version_id, v.version_no,
       b.default_version_id = v.id AS is_default,
       (SELECT COUNT(*) FROM demo_knowledge_discipline d WHERE d.knowledge_version_id = v.id) AS portraits,
       (SELECT COUNT(*) FROM demo_knowledge_summary s WHERE s.knowledge_version_id = v.id) AS summaries,
       (SELECT COUNT(*) FROM demo_knowledge_cluster c WHERE c.knowledge_version_id = v.id) AS clusters,
       (SELECT COUNT(*) FROM demo_knowledge_cluster_member m WHERE m.knowledge_version_id = v.id) AS members
FROM demo_knowledge_base b
JOIN demo_taxonomy t ON t.id = b.taxonomy_id
JOIN demo_knowledge_version v ON v.knowledge_base_id = b.id
WHERE v.state = 'saved'
ORDER BY t.code, v.version_no;
```
