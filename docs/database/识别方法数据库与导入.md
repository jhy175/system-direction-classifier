# 识别方法数据库与导入

识别方法与用户、知识库、模型连接共用 MySQL 业务库 `direction_classifier`。应用以 `dev,mysql` 启动时，Liquibase 通过 `db.changelog-users.yaml` 应用 `method/5.0.0-schema.sql` 和 `method/5.0.0-version-guards.sql`。

| 表 | 保存内容 |
| --- | --- |
| `demo_method` | 方法身份、学科体系、所有者、共享范围、复制来源以及草稿、最新版本、默认版本指针 |
| `demo_method_version` | 草稿修订号、保存版本号、固定知识版本、算法实现及源文件摘要、配置哈希、校验报告和保存信息 |
| `demo_method_stage` | 版本内的阶段策略、生效配置、完整提示词、调用参数和带版本号的阶段输出约定 |
| `demo_method_stage_model` | 阶段用途及所绑定的具体模型连接修订 |

方法与知识版本的学科体系由复合外键约束。每个方法最多有一个活动草稿。版本保存后，数据库触发器保护版本、阶段及模型绑定；默认版本可以单独切换。阶段提示词以 `python_format` 存储完整 system 和 user 模板，并附变量名。阶段输出约定包含该阶段应产生的数据字段，模型阶段还包含调用证据字段。

## 首批内置方法

教育部、WoS SSCI、WoS SCIE 各有一个方法，所有者为 `admin`。它们共享 `api-core-hierarchical-llm` 实现，分别绑定与源算法资源清单相符的已保存知识版本。簇路由、学科召回和独立精判都绑定模型连接 ID `1` 的 `qwen-plus` 配置修订。模型绑定引用修订 ID，凭据由现有模型连接模块管理。

| 阶段 | 首版配置 |
| --- | --- |
| `parse` | 结构化字段优先，支持拼接文本。召回摘要清洗后最多 2000 字符，精判用解析后的摘要 |
| `router` | LLM 选簇，允许 0 至 31 个 |
| `recall` | 动态召回 1 至 20 个候选，先从选中簇补足，再按源摘要数组顺序兜底 |
| `judge` | `v1` 提示词，单候选独立精判，使用画像拼接后的 `final_definition` |
| `post` | 高度相关最多 3 个，超出者降级。以等级、量化召回分、召回名次排序。候选精判失败时整篇失败 |
| `result` | 默认 Top 3，范围 1 至 5。输出约定同时覆盖完整候选链和最终学科列表 |

召回阶段的 `fallback_discipline_order` 保存完整学科代码序列。导入从源摘要数组读取顺序，并逐项校验所引用的已保存知识版本。教育部首项为 `0603`，SSCI 首项为 `SSCI-1`，SCIE 首项为 `SCIE-1`。

## 复现导入与校验

完成 Liquibase 迁移后，从系统项目根目录执行。模型连接需要启用、属于 `admin`，且配置为可用对话模型。

```powershell
$algorithmDir = (Resolve-Path -LiteralPath '../../学科交叉算法接口/direction-classifier').Path
$algorithmPython = Join-Path $algorithmDir '.venv/Scripts/python.exe'

& $algorithmPython -B .\scripts\import-methods.py --algorithm-dir $algorithmDir
& $algorithmPython -B .\scripts\import-methods.py --algorithm-dir $algorithmDir --model-connection-id 1 --apply
& $algorithmPython -B .\scripts\import-methods.py --algorithm-dir $algorithmDir --model-connection-id 1 --verify
```

预检读取算法源文件和知识资源。应用模式核实 MySQL 实例、知识资源清单、模型修订后，在同一事务内导入三套方法。相同配置会复用已有版本。若配置发生变化，导入保存新版本并更新最新版本指针，已选定的默认版本继续指向原版本。校验模式逐项比对已保存配置、提示词、输出约定和模型绑定。

当前数据对应方法页及后续运行适配所需的版本化配置。单篇和批量共用的执行器接入后，才能按版本取出这些配置并采集约定的阶段证据。

## 首次导入验收

2026-11-11，业务库完成三个方法的 v1 导入，三个 v1 均设为各自的默认版本。提交后使用新连接逐项核对 18 条阶段配置、9 条模型绑定和三套全库兜底顺序。重复导入复用了全部已有版本。测试库验证了保存版本、阶段与模型绑定的只读保护、跨体系引用限制、指针状态限制和单草稿限制，验证数据已回滚。
