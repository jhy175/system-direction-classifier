# Demo 环境配置与新机器迁移部署

配置日期：2026-11-11。以下命令除特别说明外，均在包含 `pom.xml`、`mvnw.cmd` 的 `system-direction-classifier` 根目录执行。

## 2. 本次发现的问题与处理过程

### 2.1 终端找不到 Maven

最初执行 `mvn -version` 报“无法识别 mvn”。项目实际上已有 `mvnw.cmd`、`mvnw`、`.mvn/wrapper`，其中指定 Maven 3.6.3，因此无需额外安装全局 Maven。

处理：使用 Wrapper；`scripts/env.ps1` 还为当前 PowerShell 定义 `mvn` 函数，将命令转交项目 Wrapper。单独打开一个新终端时需再次加载该脚本。

### 2.2 有 Java 运行环境，但缺少 JDK 和 JAVA_HOME

原有 `java -version` 显示 Oracle Java 8u421 运行环境，`JAVA_HOME` 未设置，Wrapper 直接退出。编译需要完整 JDK，只有 JRE 不能代替 JDK。

处理：下载并解压官方 Azul Zulu JDK 8u512 x64；设置 `JAVA_HOME` 指向 JDK 根目录，将其 `bin` 加到当前会话 PATH 最前面。初始化脚本固定下载地址并校验 SHA-256：

```text
68549CC971A00E4407DE1CEF569C0851C8DEE00C71EAB461FE9CA62684BB161B
```

检查命令：

```powershell
. ./scripts/env.ps1
java -version
javac -version
mvn -version
```

三者应分别显示 Java 8、javac 1.8、Maven 3.6.3，且 Maven 的 Java 路径应与 `JAVA_HOME` 一致。IDE 中也应把 Project SDK、Maven Runner JRE、Maven Importer JDK 设置为相同 JDK，并选择项目 Maven Wrapper。

### 2.3 Eden SNAPSHOT 依赖不完整

本机原先只安装了部分 Eden 基础模块。DAO 等模块引用的 HikariCP、MyBatis、Liquibase 等 Eden starter 不在本地；直接从 POM 中配置的 Sonatype 仓库下载也失败。

处理：从 Eden `2.4.x` 的固定提交获取源码。初始化脚本从 Demo 各模块 POM 提取直接依赖的 Eden 制品，通过 `-pl ... -am install` 构建所需模块及其依赖，共 37 个 reactor 项目。上游构建使用 `-DskipTests -Dmaven.javadoc.skip=true`，跳过第三方框架测试执行和 Javadoc 打包；框架主源码仍正常编译。依赖安装到默认的 `%USERPROFILE%/.m2/repository`。

Windows 下长路径会让 Git checkout 报 `Filename too long`。脚本克隆/检出时使用 `git -c core.longpaths=true`。手动准备环境时也应加该参数，并优先选择较短的工程目录。

Spring Cloud 的传递依赖解析还出现过长时间网络读取等待。项目新增 `.mvn/settings.xml`，将外部制品仓库统一镜像到 Maven Central，Eden SNAPSHOT 则使用源码安装的本地制品。`bootstrap.ps1` 和加载环境后的 `mvn` 函数自动使用这份配置；手动运行 Wrapper 时使用 `./mvnw.cmd -s .mvn/settings.xml ...`。这份项目配置替代默认用户 settings；若需要单位代理、私服或凭据，请复制为已被 Git 忽略的 `.mvn/settings.local.xml`，在副本中配置，环境脚本会优先使用该副本。

不能只复制 Demo 的源代码和 JDK 就认为依赖齐全：新机器还必须完成这一步，或使用团队保存了相同制品的 Maven 私服。

### 2.4 代码引用了框架中不存在的 MultiResult

当前 Eden 2.4.x 提供 `Result`、`SingleResult`、`PageResult`，没有业务代码引用的 `org.ylzl.eden.spring.framework.dto.MultiResult`。

处理：在应用 API 模块新增 `cn.edu.whu.irlab.systemdirectionclassifier.api.dto.MultiResult<T>`，继承现有 `Result`，提供列表 `data` 和 `build(Collection<T>)`；API、Service、Controller 改为导入应用自己的类。继续保持列表接口的 `success/code/message/data` 响应字段，不修改本机缓存中的第三方 JAR。

这项修复属于源码兼容性修复；新机器必须使用包含该修复的 Demo 源码。

### 2.5 RPC Provider 仍调用旧构造函数

`UserServiceImpl` 已扩展为依赖 UserDAO、RbacManager 和四个转换器，但 `UserProvider` 仍调用原有两参数 `super(userDAO, userConvertor)`，导致 Service 模块编译失败。

处理：同步 `UserProvider` 的构造参数和 `super(...)` 调用，将六个依赖完整传递给父类，与其他 RPC Provider 的写法保持一致。

## 3. 新 Windows 机器：从源码构建

1. 安装 Git 和 PowerShell，将修复后的完整项目复制或克隆到新机器，包括 `scripts`、`.mvn` 和 Maven Wrapper 文件。建议路径如 `D:/work/system-direction-classifier`。
2. 确保能访问 Azul 下载站、GitHub、Maven Central。若单位使用代理或 Maven 私服，在本机网络及 `.mvn/settings.local.xml` 中配置，不要提交个人凭据。已有用户级 `settings.xml` 时，应将所需代理/认证配置合并到该本地副本。
3. 在项目根目录运行初始化：

   ```powershell
   ./scripts/bootstrap.ps1
   ```

   该命令下载校验 JDK、启动 Maven Wrapper、检出固定 Eden 提交并安装所需依赖。首次运行需要联网下载，耗时取决于带宽和缓存。

   如果本机 PowerShell 执行策略阻止脚本，可仅对本次进程运行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/bootstrap.ps1
   ```

4. 将环境加载到当前终端并编译：

   ```powershell
   . ./scripts/env.ps1
   mvn -B -ntp clean compile
   ```

5. 生成部署包：

   ```powershell
   mvn -B -ntp clean package -Dmaven.javadoc.skip=true
   ```

   此处只跳过 Javadoc 生成，主源码编译和 JAR 打包正常执行。检查 reactor 所有模块均为 `SUCCESS`、最终输出 `BUILD SUCCESS`。可执行包应在：

   ```text
   system-direction-classifier-start/target/system-direction-classifier-start.jar
   ```

每次打开新终端只需执行 `. ./scripts/env.ps1`。通常无需重复安装 Eden；需要重新安装时再运行 `bootstrap.ps1`。`bootstrap.ps1 -SkipEden` 仅适用于依赖已经完整安装的机器。

项目的 Maven 父工程将测试插件放在 profile 中；`compile` 或普通 `package` 成功不能视为集成测试通过。需要运行所配置测试时，可按实际测试资源使用 `mvn -Punit-test test`。

## 4. 新机器：只部署已编译的 JAR

如果在现有机器打包后把 JAR 交付到新机器，新机器无需安装 Maven、Git 或构建 Eden。

1. 准备 Java 8 x64 运行环境；也可安装与构建机相同的 JDK 8。
2. 复制 `system-direction-classifier-start.jar` 到部署目录。
3. 确认 8082 和 9082 端口未被占用，部署账号拥有日志目录写权限。
4. 演示启动：

   ```powershell
   java -jar ./system-direction-classifier-start.jar --spring.profiles.active=dev
   ```

5. 检查启动日志，再验证管理端点和业务接口：

   ```powershell
   Invoke-RestMethod http://localhost:9082/actuator/health
   Invoke-RestMethod http://localhost:8082/api/users/1
   ```

默认 dev 配置使用 H2 内存数据库；应用重启后数据不能作为持久化业务数据保留。Redis、Nacos、Dubbo、MQ 等组件默认关闭，单纯 Maven 编译不要求启动这些服务。

长期部署时，应准备外部配置文件，替换数据库地址、账号密码和所需服务地址；如使用 MySQL，切换 datasource 配置并关闭 H2 console。启用 Redis/Nacos/MQ 等组件时，再安装对应服务、设置连接参数并验证网络连通。使用服务器的服务管理或进程管理工具配置自动启动、日志和重启策略。管理端口的访问范围按部署网络要求设置。

可以继续使用 dev profile 配合外部配置覆盖数据库和组件设置；如改用 prod profile，必须自行提供完整的 prod 配置，不能仅修改 profile 名称。

Linux 仅部署 JAR 时使用相同 `java -jar` 命令。Linux 从源码构建时需要手动安装 Linux 版 JDK 8，设置 `JAVA_HOME`、`PATH`，通过 `./mvnw` 执行与 Windows 相同的 Eden 安装和 Demo 构建；这里的 PowerShell 初始化脚本只安装 Windows x64 JDK。

## 5. 排错顺序

| 报错/现象 | 优先检查 |
| --- | --- |
| 找不到 `mvn` | 加载 `scripts/env.ps1`，或使用 `./mvnw.cmd` |
| `JAVA_HOME not found` | JAVA_HOME 是否指向 JDK 根目录 |
| `No compiler is provided` | 是否误用 JRE；检查 `javac -version` |
| `MultiResult` 找不到 | 是否使用了本次修复后的源码 |
| Eden SNAPSHOT 找不到 | 是否成功运行 bootstrap 安装依赖、是否误用其他 Maven 本地仓库 |
| `Filename too long` | Git 的 `core.longpaths`、工程路径长度 |
| 依赖下载超时/证书错误 | 网络、代理、制品仓库及 JDK 证书；不要禁用证书校验 |
| IDE 仍报错，命令行已成功 | 重新导入 Maven；核对 SDK、Runner JRE 和 settings.xml |
| JAR 启动报错 | 区分端口占用、配置缺失、数据库初始化和外部服务连接问题 |
